## Decisions carried in — do not relitigate

**The landing page becomes generated — Ben, 2026-08-22.** Its four binding clauses:

1. **A subcommand under an existing `py/main_*.py`**, never a new entry point, never a `sys.path`
   prelude. It names `main_authored.py` as the obvious host and leaves the choice to the session.
2. **Derive the subtree list from the site, not from a literal** — one entry per
   `gh-pages/<subtree>/index.html`, the way `py/main_wlc_redirect_stubs.py` derives its stub set
   from `git ls-files`. **Descriptions cannot be derived and stay authored**; a subtree with no
   description is a gap to fill, not a link to emit bare.
3. **Otherwise reproduce the current page's shape** — no stylesheet, a `<ul>` of one-line entries,
   the closing pointer at the README. The `Do not edit by hand.` breadcrumb from
   `mb_cmn/provenance.py`'s `generated_html_comment` replaces today's `Hand-written… No program
   writes this file.` comment.
4. **`gh-pages/wlc/index.html` stays hand-written and is out of scope.**

That decision defers the generator to "the first arriving subtree — not before… It is a small job
and Ben can pull it forward at any point; nothing else waits on it." **This plan pulls it forward**,
and the reason is better than the one it was waiting for: the page acquires real content now, so a
generator emitting a fixed one-item list is no longer the dead weight the decision feared.

**A citation Ben can edit is not a reason for a stub; it is a URL to update.** Ben, 2026-08-22, in
`py/wlc_redirect/stubs.py`'s docstring. So every in-repo citation of the old README URL is
repointed, not redirected.

difference: **authored data** and **derived manifest**.

other half through a derivation that cannot express it.

### The phase as planned

New package `py/author_site/`, per `doc/agent-planning-principles.md` §"Prefer New Files For New
Features":

- `py/author_site/site_index.py` — the entry data types and the body builder.
- `py/author_site/published_subtrees.py` — the derived manifest: `git ls-files -z -- gh-pages`
  filtered to `*/index.html` one level down, plus the authored per-subtree descriptions. **Copy
  `py/wlc_redirect/stubs.py`'s `published_pages` shape**, including its raise-on-empty guard: an
  empty derivation must fail, never emit a manifest of nothing.

Host: **`py/main_authored.py`, new subcommand `gen-site`**, beside `gen-misc`. That module already
writes a sibling's `index.html` under `gen-mam-parsed-docs`, and its `build_parser()` is factored
out so a test can read the subcommands off it. Destination is `paths.gh_pages_dir() / "index.html"`.

**Register it in two places or the suite fails.** `py/tests/test_entry_point_subcommands.py` checks
that each entry point's `Subcommands:` docstring block and its parser name the same set, in both
directions — so `gen-site` goes into `main_authored.py`'s module docstring as well as into
`build_parser()`. That lint exists because `main_accgram.py` drifted exactly this way.

Render with plain `mb_html` — `WriteCtx`, `heading_level_1`, `unordered_list`, `anchor_h`, `para`,
`horizontal_rule` — and `provenance.generated_html_comment(__file__)`. Nested lists are supported
(`flatten` accepts an htel inside a licont), which is how the Ḥakirah entry's two annotation
sub-bullets are expressed. Two assertions in `htel_mk` will bite a page made almost entirely of
composed strings and anchors: contents may not **begin or end** with a space-bearing string, and no
string may contain a double space. `["Part 1: ", anchor]` and `[anchor, " (presented at …)"]` both
pass; a stray `"… "` at the end of a licont does not.

**Do not route this page's text through `author.dollar_sub`.** Its `_check_no_undollared` raises on
any un-`$`-prefixed romanization key, and this page's titles are full of them — *tsinnorit*,
*maqaf*, *qadma*, *paseq*, *shewa*. `main_authored.py`'s own `_gen_index_html` already builds an
index with bare `mb_html` for the same reason; follow it.

**Checkpoint before writing any new content.** Generate, then `git diff gh-pages/index.html`. This
is the only moment a faithful-generator claim can be proved, which is why it is a checkpoint rather
than folded into Phase 2; it is not pre-fragmentation but the "risky refactor that preserves
existing behavior" `doc/agent-planning-principles.md` allows a boundary for.

**A correction to the 2026-08-22 decision's stated expectation, carried in.** It says "the first
regeneration's diff should be the breadcrumb comment and the added entries and nothing else". That
cannot hold, and the reason was measured rather than guessed: `mb_html`'s serializer emits **no
indentation** and puts `<title>…</title>` on **one line**, whereas both hand-written pages here
indent `<ul>` by 4 and `<li>` by 8 and split the title across two lines. Compare
`raw.githubusercontent.com/bdenckla/MAM-with-doc/main/gh-pages/misc/index.html`, which
`main_authored.py` writes today, against `head -8 gh-pages/index.html`. So the expected Phase 1 diff
is **three** things — the breadcrumb line, the lost indentation, and the joined `<title>` line — and
anything beyond those three is a finding. The two hand-written pages were evidently written to look
like an older serializer's output; nothing depends on their whitespace.
