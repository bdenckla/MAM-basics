Reading MAM-simple: JSON Format

The JSON format mirrors the XML structure: the same hierarchy (book24 → book39 → chapter → verse → child elements) and the same element types appear in both, with XML elements and attributes mapped to JSON objects and fields.

For the element types and verse attributes, see the XML guide.

Root object

{
  "provenance": "This file was generated by MAM-basics/py/main_mam_simple.py.",
  "consumer_notice": {
    "summary": "...",
    "critical_rules": ["...", "..."],
    "documentation": "https://bdenckla.github.io/MAM-basics/MAM-simple/reading-mam-simple.html#consumer-notice"
  },
  "versification-tradition": "vtmam,vtbhs,vtsef",
  "contents": [ "...", "...", "..." ]
}

The root object has exactly these four fields, in this order. provenance identifies the generator. consumer_notice is the warning label described in the consumer notice; its actual summary and rule strings are not abbreviated in the generated files.

The versification-tradition field is a string holding a comma-separated set: every versification tradition whose cv-labels this file carries, drawn from vtmam, vtbhs and vtsef, in that order. It is a string rather than a JSON array so that it stays identical to the XML format's attribute of the same name, where the XML guide sets out the three values and which book groups take each. The contents array contains book39 objects and parashah-marker objects. (Throughout this section, ["...", "...", "..."] is used to express "one or more elements" while still being valid JSON.)

Book39 objects

{
  "type": "book39",
  "osisID": "Ruth",
  "contents": [ "...", "...", "..." ]
}

The contents array contains chapter objects and parashah-marker objects (same types as in XML).

Chapter objects

{
  "type": "chapter",
  "osisID": "Ruth.1",
  "contents": [ "...", "...", "..." ]
}

The contents array contains verse objects and parashah-marker objects.

Verse objects

Simple verses (no special markup) have a text field directly:

{
  "type": "verse",
  "osisID": "Ruth.1.1",
  "text": "וַיְהִ֗י בִּימֵי֙ ..."
}

Complex verses (with legarmeih, ketiv/qere, etc.) have a contents array instead:

{
  "type": "verse",
  "osisID": "Ruth.1.2",
  "contents": [
    { "type": "text", "text": "וְשֵׁ֣ם הָאִ֣ישׁ ..." },
    { "type": "lp-legarmeih" },
    { "type": "text", "text": " מַחְל֤וֹן ..." }
  ]
}

Parashah-marker objects

{ "type": "spi-pe2" }

Parashah-marker objects can appear:

  • as a child of the root object's contents array, between book39 objects (e.g., between 1 Samuel and 2 Samuel)
  • as a child of a book39 contents array, between chapters
  • as a child of a chapter contents array, between verses
  • as a child of a verse contents array, within a verse

Ketiv/qere objects

A ketiv/qere pair is a kq object whose contents holds a kq-k object (the ketiv) and a kq-q object (the qere), in the order that MAM's rendered pages on Hebrew Wikisource have. Those pages usually have the ketiv first, but they have the qere first in about one pair in eight, as at Lam.1.18:

{
  "type": "kq",
  "contents": [
    { "type": "kq-q", "text": "הָֽעַמִּ֗ים" },
    { "type": "kq-k", "text": "עמים" }
  ]
}

Identify the two by type, never by position; see Ketiv/Qere in the XML guide.

Silluq before a later meteg

A silluq-before-meteg object represents an atom with a silluq before a meteg. The object has type, text, and letters-with-silluq, without contents. It follows the XML parameter contract. For example, this part of a verse’s contents keeps sof pasuq outside the annotation:

[
  {
    "type": "silluq-before-meteg",
    "letters-with-silluq": "לכלֽהנה",
    "text": "לְכֻלָּֽהְנָֽה"
  },
  {
    "type": "text",
    "text": "׃"
  }
]

Generic text consumers take only text; they never append letters-with-silluq as running text. The two current cases are 1 Kings 7:37 and Job 4:12.

Legarmeh and paseq

The lp-legarmeih type identifies legarmeh, which is part of the cantillation system. The lp-paseq type identifies paseq in the narrow sense, which is not part of the cantillation system, or is, at most, at the periphery of the cantillation system.

An edition or other application may use or discard this distinction.
